# 一张图基础地图组件：功能与技术架构梳理

梳理日期：2026-09-07。依据当前目录源码进行静态分析；README 作为背景资料，功能判断以实现为准。本次未运行浏览器验收、GeoServer 联调或修改业务代码。

## 1. 项目定位

当前组件是一个 Vue + OpenLayers 的二维地图前端，已有独立页面入口和 DataV 嵌入入口。适合作为独立“一张图”项目的地图基础，但目录内不包含后端、数据库、登录权限、服务目录管理等完整平台能力。

## 2. 主要功能

| 功能 | 当前代码能力 | 边界与条件 |
| --- | --- | --- |
| 地图浏览 | 平移、缩放、初始中心和投影配置 | 默认 EPSG:4326；未发现自定义投影注册 |
| 底图切换 | 矢量/影像切换，XYZ 瓦片 | 示例可使用天地图，未配 Key 时使用 OSM/Esri；天地图以 XYZ URL 模板接入 |
| 业务图层 | WMS 叠加、图层名称过滤、显隐 | WMS 实际使用 ImageWMS + ImageLayer；透明度支持配置，未发现交互滑块 |
| 综合搜索 | 高德地址地理编码、WFS 属性模糊检索 | 高德限定北京；WFS 需配置 searchFields，可配置 sortField/searchTypeName |
| 搜索结果 | 按地名地址/图层分 Tab、列表分页、定位及临时矢量高亮 | WFS 每批取 100 条直到取完，界面每页展示 10 条，并非按界面页码请求 |
| 属性查询 | 点击查询当前可见 WMS 对应的要素属性 | 实际通过 WFS 查询点击位置周边 5 像素 BBOX，每图层最多 20 条；非 WMS GetFeatureInfo |
| 分屏对比 | 左右选择业务图层、双地图同步中心和缩放 | 存在 Map 命名冲突，需修复后验证 |
| 卷帘对比 | 选择叠加图层、拖动分界线 | 第二地图实例叠加，通过 CSS clip-path 裁切 |
| 测量 | 测距、测面、实时提示、双击结束及清除 | 使用 OpenLayers 球面长度/面积计算；无成果持久化 |
| 标绘 | 点、线、面、圆、矩形，连续绘制及清除 | 未发现编辑保存、导入导出或协同能力 |
| 缓冲查询 | 绘制范围或点选源要素，设置米制距离及目标图层，展示缓冲和结果 | Turf 生成缓冲面；BBOX 取数后近似筛选，最多取 5000 条 |
| 截图 | 整个地图组件界面下载为 PNG | 依赖画布及图片跨域条件；包含工具栏、面板等 |
| 外部集成 | data 配置，ready/map-click 事件，searchExternal/clearPlaceSearch 方法 | DataV 包 events 为空，尚未形成完整宿主事件映射 |

App.vue 示例主动关闭截图、测距、测面和标绘按钮；这些功能有代码实现。组件未显式关闭的工具默认展示。DataV 配置面板也为上述四个工具设置了关闭默认值。

## 3. 当前技术架构

技术依赖声明：Vue ^3.5.0、OpenLayers（ol）^10.7.0、Vite ^7.0.0、TypeScript ^5.0.0、@turf/buffer ^7.4.0、html2canvas ^1.4.1。这些是 package.json 声明范围，不代表已核验的安装版本。

```text
独立网页入口                       DataV 宿主
index.html → main.ts → App.vue      datav-package/index.js
             │                     ↓ 加载 widget.js
             │                     datav-entry.ts：配置归一化、挂载
             └──────────┬──────────┘
                        ↓
                 MapWidget.vue
          界面、状态、工具交互、查询逻辑
                        ↓
         OpenLayers 地图、图层、矢量、绘制
            ├─ XYZ → 底图服务
            ├─ ImageWMS → GeoServer WMS 图像
            ├─ fetch WFS → GeoJSON → 属性/定位/分析
            ├─ 高德地理编码 → GCJ-02 转 WGS84 → 定位
            ├─ Turf → 缓冲几何
            └─ html2canvas → PNG
```

状态主要由 Vue ref/computed/watch 管理，未见 Pinia、路由层或统一 API 服务层。MapWidget.vue 约 1358 行，集中承担界面、地图生命周期、网络请求、坐标处理和工具逻辑；配套样式约 842 行。

主要文件职责：

| 文件 | 职责 |
| --- | --- |
| src/App.vue | 示例业务配置：北京行政区划、轨道线路/站点、民生信息和底图 |
| src/MapWidget.vue | 地图组件、业务工具和服务访问 |
| src/map-widget.css | 地图布局、工具栏、面板、结果列表等样式 |
| src/datav-entry.ts | DataV 配置转换、默认业务图层及 Vue 挂载 |
| datav-package/index.js | protocol 2 生命周期适配；更新配置时卸载并重新挂载 |
| datav-package/package.json | DataV 服务、视图、工具开关配置面板 |
| vite.config.ts | 独立网页构建、本地 8081 端口和 GeoServer 开发代理 |
| vite.datav.config.ts | IIFE 组件构建、CSS 注入、向原 frontend 自动同步资源 |

## 4. 独立项目需要优先解决的问题

1. **分屏 Map 命名冲突。** `import Map from 'ol/Map.js'` 遮蔽原生 Map；preSplitVisibility 的初始化和赋值也调用该导入。这里需要键值集合，却创建了地图对象，可能影响组件初始化及分屏关闭恢复。应将地图类改用 OlMap 别名，原生集合显式区分，并验证运行行为。
2. **构建存在目录外写入。** DataV 构建自动同步至 `../frontend/public/datav-map`；独立项目应移除或改成显式可选发布步骤。普通网页构建和组件构建共用 dist，也应拆分输出目录。
3. **业务配置耦合。** 本地地址、bjchy 工作区、北京图层、搜索展示字段分布在 App.vue、datav-entry.ts 和组件中。默认图层名称已带 bjchy 前缀，仅更改 workspace 不会全部替换。应集中到运行时配置。
4. **空间分析精度有限。** 缓冲面由 Turf 生成，结果却采用目标几何外包框中心点至源几何的 EPSG:3857 距离筛选；存在投影距离偏差，也不能准确判断线面与缓冲面的相交关系。5000 条上限可能截断结果。正式分析应使用明确的空间谓词、适当坐标系及完整分页。
5. **坐标约定需要统一。** 部分 WFS 请求未传 srsName，读取时却按 EPSG:4326 解释；默认视图、服务坐标与自定义投影需约定并校验，不能仅靠 projection 字符串保证任意坐标系支持。
6. **配置更新会重建状态。** 对 data 深度监听后重建 View 和图层，可能重置视图或移除临时分析图层；DataV 更新则重新挂载整个组件。应区分视图、图层与工具配置更新。
7. **工程与服务边界待补齐。** 当前未见测试脚本、独立类型检查脚本、统一请求取消/超时处理、后端和权限管理。开发代理不等于生产代理，独立部署需落实 GeoServer 同源路由或 CORS 配置。

## 5. 建议的独立项目结构

建议保留现有组件的功能资产，建立清晰的应用、地图内核、功能工具、服务和适配器边界。以下为设计建议，尚未创建或实施。

```text
onemap-app/
  src/
    app/                  # 独立应用入口、页面布局
    config/               # 底图、服务、图层、字段、功能开关
    map/
      core/               # 初始化、图层工厂、坐标、生命周期
      components/         # 画布、工具栏、图层面板、结果面板
      features/           # 搜索、属性、测量、标绘、缓冲、分屏、卷帘
      services/           # WFS、地址搜索、请求与错误处理
      types/              # 配置、结果、事件类型
      styles/
    adapters/datav/       # 可选 DataV 宿主适配
  public/config/          # 可部署时替换的非敏感配置
  tests/                  # 关键交互、空间查询和集成验证
  docs/
```

实施顺序建议：先修复地图基础运行问题和构建耦合，再集中配置、分离功能模块，随后联调地图服务并验证查询精度与关键交互。登录、权限、目录管理、标绘保存和审计作为独立平台需求另行确认。需求确认、最终 UI 确认和生产发布等按项目 AGENTS.md 的人工批准要求执行。
